# 1. Что такое harness?

> **Гайды направляют до действия; сенсоры исправляют после него.**

Агент для написания кода (Claude Code, Codex, Cursor, …) быстрый, неутомимый и понимает всё буквально.
Предоставленный сам себе, он легко добавит сервис, который никому нельзя вызывать, отредактирует миграцию БД,
которая уже выполнилась в продакшене, или «починит» падающий тест, ослабив проверку. **Harness** («упряжь») —
это структура вокруг агента, которая не даёт этому случиться. Не за счёт ручного ревью каждой строки, а за счёт
двух видов сигналов:

| | **Гайды** (feedforward, упреждающая связь) | **Сенсоры** (feedback, обратная связь) |
|---|---|---|
| Когда | *до* того, как агент действует | *после* того, как агент подействовал |
| Зачем | показать, как здесь выглядит «хорошо» | точно сказать, что пошло не так и как исправить |
| Примеры в air-harness | `AGENTS.md`, навыки (`harness/skills/*/SKILL.md`), рубрика ревью, сообщения правил, промпты | проверка топологии `docker-compose.yml`, проверка миграций, ruff, semgrep, контрактные тесты, LLM-ревью, оценка поиска |
| Что будет, если только это | правила, которые никто не проверяет | агент повторяет одну и ту же ошибку |

Гайд без сенсора — правило, которое никто не проверяет. Сенсор без гайда — урок, которому никто не учит.
Harness связывает их в пары и **измеряет** и то, и другое.

## Вычислительные и инференциальные

Каждый гайд и сенсор относится к одному из двух видов:

- **Вычислительный (computational)** — детерминированный, дешёвый, точный: парсер, линтер, тест. Один и тот же
  вход — один и тот же ответ. Такие сенсоры могут **блокировать** (ронять сборку).
- **Инференциальный (inferential)** — судит LLM: агент-ревьюер, судья в оценке поиска. Полезен там, где нужно
  суждение, но шумит. Остаётся **рекомендательным (advisory)**, пока его точность на реальных диффах не измерена.

Главное эмпирическое правило дизайна: *если правило можно сделать вычислительным — делайте его вычислительным*.
Текст в гайде — последнее средство, а не первое.

## Почему harness — это продукт, а не папка

Шаблоны начинают расходиться в момент копирования. air-harness устроен как продукт:

- **Описан как данные** — каждый гайд и сенсор — запись в одном манифесте (`harness.yaml`): вид, категория,
  где запускается (плоскость), когда запускается (стадия), блокирует ли, с каким гайдом связан.
- **Версионируется** — распространяемая часть — образ раннера с зафиксированными версиями инструментов; проекты
  закрепляют его тег и обновляются сменой тега (`harness/CHANGELOG.md` описывает ожидаемый эффект новых правил).
- **Сам себя тестирует** — у каждого вычислительного сенсора есть *засеянные дефекты* (фикстуры, на которых он
  обязан сработать) и чистые фикстуры (на которых он обязан молчать). `make harness-selftest` доказывает, что
  молчащий сенсор — не слепой.
- **Измеряется** — каждый запуск сенсора дописывается в журнал (ledger). `make harness-stats` показывает, какие
  сенсоры срабатывают часто (связанный гайд слаб), какие никогда, а какие слепы. Это **цикл управления
  (steering loop)**.

## Что входит в air-harness

1. **Сам harness** — манифест, раннер, сенсоры, правила, рубрика, навыки, промпты, хуки и интеграция с CI.
2. **Эталонная система**, которую регулирует harness, — чтобы всё работало на реальном коде с первой команды:
   три Python-сервиса (gateway, content, search) с межсервисными вызовами, подписанными Ed25519, PostgreSQL с
   отдельной ролью и схемой на сервис, миграции Flyway, Kafka, Prometheus — всё в одном `docker-compose.yml`.
3. **Продуктовый интерфейс** — `run.sh` (запустить всё и вывести все адреса), `help.sh` (руководство прямо в
   терминале) и готовые промпты «следующих шагов» для агентов.

## Словарь

| Термин | Значение |
|---|---|
| **Гайд (guide)** | Всё, что направляет агента до действия (документ, навык, сообщение правила, промпт). |
| **Сенсор (sensor)** | Команда, проверяющая результат после действия агента. Код выхода 0 = пройдено. |
| **Плоскость (plane)** | Где запускается сенсор: `static` (контейнер без сети), `live` (контейнер в сети проекта: LLM, стенд), `host` (ваша машина / CI через make и docker compose). |
| **Стадия (stage)** | Когда запускается сенсор: `pre-commit` < `integration` < `pipeline` < `continuous`. Качество — как можно левее. |
| **Блокирующий** | Упавший блокирующий сенсор делает отчёт RED (красным). Рекомендательные только информируют. |
| **Слепой (blind)** | Сенсор, который не смог запуститься (нет инструмента, LLM недоступна, таймаут). Проблема harness, а не кода — и никогда не считается пройденным. |
| **Засеянный дефект** | Фикстура с известной ошибкой (`# expect: <правило>`), доказывающая, что сенсор ещё срабатывает. |
| **Отчёт** | `.harness/report.md` — единственный документ, который агент читает после каждого изменения. |
| **Журнал (ledger)** | `.harness/ledger.jsonl` — одна строка на запуск сенсора; данные для цикла управления. |
