How it works

  1. Guides steer the agent before it acts: AGENTS.md, skills, the review rubric, prompts.
  2. The agent edits the code.
  3. Sensors check the change: topology, migrations, lint, organisation rules, the review agent; then unit, contract and search-quality tests against the running stack.
  4. The harness writes one report: GREEN, or RED with how to fix each blocking failure.
  5. The agent reads it and fixes; its Stop hook will not let it finish while the static sensors are RED.

Every run lands in the ledger: the Agent tab shows it as a timeline, the Harness tab shows each sensor's latest result and whether its seeded defects still prove it can fire.
